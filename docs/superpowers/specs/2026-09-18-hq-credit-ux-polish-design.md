# 总部积分后台错误提示与门店同步展示优化

日期：2026-09-18

状态：口头方案已确认，待书面设计审阅

目标分支：`codex/m4-release-ready`

## 1. 目标与范围

解决“建立待确认批次”失败但管理员在表单附近看不到原因的问题，收紧总部 Web 后台的字号与间距，并让左侧门店区域只展示**当前这次手动同步的变化**。补充一次性 CSV 的查看说明。本期不改变兑换码生成、下载、兑换、扣分、门店来源、权限、数据库结构或小程序界面。

## 2. 已比较的方式与选择

- **采用：临时变更摘要。** 同步 API 在本次响应中返回变更门店的名称和变化类型；浏览器仅在当前页面内显示。重新登录、退出登录或刷新页面后不恢复这份摘要。既有完整门店目录继续留在服务端，供门店发码下拉框使用，不在左侧常驻展示。此方式满足“只看这次更新”，不增加持久化状态。
- 备选：常驻完整门店列表并高亮最近变化。容易让下次登录仍看到旧门店，不符合本次要求。
- 备选：把“上次看到的同步版本”存到浏览器或数据库。需要额外状态与清理规则，本期没有必要。

## 3. 左侧门店区域

保留“同步门店信息”按钮和最近成功同步时间。点击同步成功后，只显示本次的变化条目：新增、改名、停用、重新启用。每条显示**当前可识别的门店名称**及“新增／改名／停用／恢复”标签；改名可附旧名以便辨认。没有变化时只给出“同步完成，本次没有门店变化”的短提示，不渲染门店列表。失败时保留原有目录和最近成功时间，在按钮附近显示失败原因，不留下误导性的变更摘要。退出登录或重新进入页面时清空本次摘要；此后即使服务端有历史同步记录，也不重放旧变更。

同步服务仍在事务中新增、更新、停用门店，只把本次**非敏感的变更摘要**随成功响应返回。`GET /api/hq/stores` 保持本地目录与最近同步时间，不返回历史变更清单，也不触发来源请求。变更名称不得写入新的服务日志。发码下拉框仍可选择所有已同步、已启用的门店。

## 4. 建批次错误提示

“建立待确认批次”表单内、按钮上方预留清晰的错误区域，使用 `role="alert"`。提交前检查赠码原因至少 4 字，并在该输入项旁写明“至少 4 字”；缺失或不合法时聚焦对应字段，显示直接可执行的提示，不发请求。其他前端可判断的必填、数字范围、日期错误也在表单附近说明。服务端拒绝请求或网络失败时，同一区域显示安全、可理解的错误；保留已填内容，不只更新页面顶部通知。成功时清空表单错误，刷新批次列表，并在表单附近提示“已建立待确认批次，尚未生成兑换码”。顶部全局通知仍可用于登录与同步等操作，但不能作为建批次失败的唯一反馈。

服务端校验仍是最终权威；不因为前端提示而放宽审批、人数、面额或有效期规则。错误文案不得回显密钥、兑换码或用户输入全文。

## 5. 视觉与 CSV 指引

仅调整总部 Web 后台：主标题、卡片标题、输入框、按钮和表格的字号与垂直间距逐级收紧，使桌面端更紧凑；正文和表单文字不低于 16px，交互焦点与对比度保持清晰。小程序适老化令牌不变。左右卡片在窄屏继续顺序堆叠，批次表格仍可横向滚动。

在“确认并下载 CSV”附近增加简短说明：点击确认后浏览器下载 `lejoy-codes-批次号.csv`，可在浏览器下载列表或 Mac 下载文件夹中找到，用 Numbers／Excel 打开；兑换码在第一列。明文码仅在这次激活响应中提供，系统不支持再次查看。说明不改变实际 CSV 格式或一次性下载机制。

## 6. 验证与发布

测试覆盖：短于 4 字的原因在表单附近提示且不发请求；服务端错误仍在表单附近可见且不清空输入；同步返回只含本次新增／改名／停用／恢复名称，重复同步返回空摘要；重新登录不恢复摘要；目录仍供下拉框使用；CSV 说明与原有一次性下载语义一致。运行相关 Vitest、`pnpm check`、Web 构建和全量 `pnpm test`。部署前不自动建立批次或激活兑换码；发布后检查总部页面、健康接口及 PM2 单实例，并由管理员实际点击同步验证“本次无变化”的显示。
