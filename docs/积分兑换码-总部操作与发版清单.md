# 乐享 AI 积分兑换码：总部操作与发版清单

适用范围：总部 Web 后台配码、线下交付、顾客小程序兑换。本期没有微信在线支付或顾客购码入口。店长在线下向总部申请／结算，再免费向顾客赠码。

## 开发与测试负责人（正式发布前）

- [ ] 确认工作分支、提交号、数据库迁移 SQL 和部署产物均来自同一版本；检查未纳入 `.env`、初始密码、TOTP 种子或明文兑换码。
- [ ] 运行 `pnpm test`、`pnpm check`、`pnpm check:mp`、`pnpm build`、`pnpm --dir miniprogram build:weapp:prod`；生产小程序地址校验必须通过。
- [ ] 使用**独立的、库名以 `_test` 结尾的 MySQL 测试库**，应用迁移后设置 `TEST_DATABASE_URL` 跑 `server/credits/redeem.integration.test.ts`；确认并发同一码只入账一次、流水唯一、写流水失败会回滚码状态和余额。没有独立测试库时，此项未完成，不得以跳过的单测替代。
- [ ] 测试总部账号登录：密码／动态码错误提示一致；连续失败被限速；首次登录只能改密；会话闲置、绝对过期、登出和账号停用均失效；旧 `/admin` 登录 Cookie 不可调用 `/api/hq/*`；写请求缺少 CSRF 或来源错误被拒绝。
- [ ] 当前登录限流状态保存在 fork 单实例进程内，进程重启会清空计数；上线前核对 Nginx 的来源地址转发配置，并由运维监测暴力尝试。若后续扩为多实例，须先迁移为共享限流存储。
- [ ] 测试待确认批次没有码、不可兑换；激活后一次性 CSV 下载；丢失 CSV 后不能再次读取明文，只能停用未用码并重建；过期／已用／已停用码均不加分。
- [ ] 微信真机检查：积分中心大字、可粘贴兑换码、成功后余额与明细同步刷新、错误态可理解、无在线购买／支付按钮；积分不足页面可进入积分中心。

## 运维负责人（须先获单独生产授权）

- [ ] 在执行任何生产迁移前，取得明确的生产上线授权，备份生产数据库并验证可恢复；逐条复核 `drizzle/0003_typical_quicksilver.sql` 与 `drizzle/0004_flashy_unicorn.sql`：新增六张表、`redeem` 枚举值及关联列，并扩展批次事件的交付确认动作；不重建或删除既有积分数据。
- [ ] 说明 `scripts/deploy/02-deploy.sh` 当前会自动运行 `pnpm db:push`：**未获生产迁移授权前，不得运行该部署脚本。** 仅推送代码不等于授权迁移。
- [ ] 在服务器受控终端、root 身份建立仅 root 可读的 TOTP 加密密钥：`pnpm exec tsx scripts/hq-admin.ts init-key`。密钥文件不写入 `.env`、仓库、聊天或部署日志；备份方式按公司密钥管理制度执行。
- [ ] 首次账号必须在身份核对后交互式执行 `pnpm exec tsx scripts/hq-admin.ts create <总部账号>`；初始密码与 TOTP 绑定密钥仅在现场终端显示一次，不截图群发、不写工单明文。
- [ ] 上线前确认 `HQ_ORIGIN`（默认 `https://api.hxzhineng.xyz`）、证书、Cookie 安全属性、总部后台 `/hq` 与 `/api/hq/*` 同源；不能把静态 `/hq` 返回 200 当作登录验收。
- [ ] 获授权后执行部署、迁移与健康检查；核对 PM2 仍为 fork 单实例、`/api/mp/health` 正常、现有功能无回归。生产令牌、密码、原码不进入日志。
- [ ] 部署后由总部真人完成双因素登录、首次改密、登出与重新登录；由两位测试用户在微信真机验证兑换成功、重复兑换无第二次加分、余额与流水一致。

## 总部管理员（正式运营）

- [ ] 建立门店稳定编号与名称，核对店长身份和线下申请数量、每码积分及有效期。
- [ ] 门店采购：先在线下收款／结算并保存外部凭证编号；活动赠码：先取得总部审批，并填写审批编号、审批人和赠码原因。后台不存付款账户、凭证照片或支付密码。
- [ ] 在后台建立待确认批次；再次核对门店、面额、数量（单批最多 1000）、有效期、用途和凭证／审批编号。待确认批次尚无可交付码。
- [ ] 由授权人员点击“确认并下载 CSV”；下载成功后立即将一次性文件移至受控存储，再通过安全渠道交付对应店长，不通过公开群传播。交付后在后台点击“确认已安全交付”，写明接收人和交付方式。
- [ ] 定期核对每批“已分配 = 已兑换 + 未兑换 + 已过期 + 已停用”及积分总量，复核操作记录。
- [ ] CSV 丢失或疑似泄露：在后台写明原因，停用未兑换码；已兑换积分不回撤。核对后新建批次重新交付。
- [ ] 动态码设备丢失：完成总部身份核验后，由服务器受控终端执行 `pnpm exec tsx scripts/hq-admin.ts reset-totp <总部账号>`，记录原因；原会话会被撤销。
- [ ] 管理员小程序积分不足时，仍按普通用户规则扣费；任何人工补分都须核对目标用户、操作者和数额，运行受控命令，不因管理员身份自动补分。

## 店长与顾客

- [ ] 店长只接收总部授权批次，向顾客**免费**赠送兑换码；不得自行生码、改面额或在小程序内转售。
- [ ] 顾客打开“积分中心”，输入或粘贴 12 位兑换码；成功后立即查看新余额与“门店兑换码赠送积分”流水。
- [ ] 无效、已用、过期或停用时，根据页面提示向店长核对；不要反复猜码。网络不畅可主动重试，同一码最多入账一次。

## 暂不开放

- [ ] 微信在线付费充值、店长线上采购、任意账号自动补分、首次真实批次运营面额均须另行审批；本期不启用。
