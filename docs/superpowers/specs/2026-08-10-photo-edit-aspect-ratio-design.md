# 修图输出尺寸按原图比例自适应设计

## 背景与目标

生产环境将 `ARK_IMAGE_EDIT_SIZE` 固定为 `1152x1536` 后，竖版照片的生成耗时由约 70 秒降至 20 多秒，但横图也被强制生成竖版，造成构图变化和人物变形。

本次修复的目标是保留 1536 像素速度档，同时严格跟随原图宽高比，不增加前端功能，不改变积分规则、模型或其他生图链路。

## 方案

`aiEditImage` 在调用 Seedream 前读取原图尺寸，再把原图等比缩放到最大 `1536x1536` 画布内：

- 3:4 原图输出 `1152x1536`；
- 4:3 原图输出 `1536x1152`；
- 16:9 原图输出 `1536x864`；
- 1:1 原图输出 `1536x1536`；
- 其他比例按原比例计算：长边固定为最大边，短边按比例计算后四舍五入到最接近的 16 像素倍数，不裁切、不拉伸。若短边会低于 512 像素，则在调用模型前停止并返回不支持该极端比例，避免悄悄改变构图。

配置从固定宽高语义改为最大边语义：新增 `ARK_IMAGE_EDIT_MAX_EDGE`，生产值为 `1536`。保留 `ARK_IMAGE_EDIT_SIZE` 作为旧部署兼容输入：若它是 `宽x高`，取两者较大值作为最大边；若是 `1.5K`、`2K` 等旧档位，则继续沿用旧模型档位行为，避免未同步环境的部署启动失败。

## 数据流与错误处理

1. 服务端下载当前账号已安全登记的原图，仅用于读取宽高。
2. 无法下载或无法识别 PNG、JPEG、WebP 尺寸时立即终止，不调用图像模型，避免错误构图和无效扣费。
3. 根据原图比例计算 Seedream `size`，再发起一次图像编辑请求。
4. 只有 Seedream 明确返回“不支持该尺寸”的 400 响应时，才按现有逻辑降级到最近的标准宽高比；其他错误不自动重试生成，避免重复成本。

尺寸读取会增加一次原图下载。当前图片已存储在 OSS，文件通常较小，这个开销相对模型生成耗时可忽略；不改上传格式和存储结构。

## 测试与发布

回归测试覆盖：

- 竖图生成 `1152x1536`；
- 横图生成 `1536x1152`；
- 16:9 和方图保持原比例；
- 无法识别尺寸时模型调用次数为零；
- 非尺寸类服务错误不触发第二次生成；
- 故事配图及普通文生图参数不受影响。

验证顺序：定向单测红灯 → 最小实现 → 定向单测绿灯 → 全量测试 → 生产构建校验 → 提交推送 → 运行 `scripts/deploy/02-deploy.sh` → 公网健康检查。部署后保留 Seedream 5.0 Pro，仅将生产尺寸配置切换为 `ARK_IMAGE_EDIT_MAX_EDGE=1536`。

## 不在本次范围

- 不更换 Seedream 模型；
- 不修改提示词、积分、前端页面或图片上传压缩；
- 不承诺固定生成时长，模型排队波动仍可能存在。
