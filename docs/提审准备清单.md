# 乐享AI 小程序提审准备清单

> 用法：由每组负责人逐项执行并打勾；不能确认的项目保留未勾选，写明负责人和预计完成日。涉及法律结论、类目选择和隐私文本的事项，以微信后台最新要求及法务意见为准。

## 项目负责人/法务：主体、资质与文本

### 主体与类目

- [ ] 确认小程序主体变更已完成，后台主体名称与营业执照完全一致。
- [ ] 确认运营主体名称已替换“关于乐享AI”页的 `TODO（运营填写）`。
- [ ] 完成小程序备案，并保存备案编号、审核截图和可查询结果。
- [ ] 根据小程序实际能力向微信确认并选择“深度合成”相关类目；不要凭旧截图猜类目。
- [ ] 根据生活百科问答能力向微信确认并选择“AI问答”相关类目。
- [ ] 核对所选类目需要的许可证、承诺函或其他资质，并逐份上传有效期内材料。
- [ ] 确认产品描述为“食物营养信息查询、生活百科”，不宣传为医疗诊断或健康咨询。
- [ ] 确认本期没有虚拟支付、故事视频、分享卡片、订阅消息或其他未验收功能。

### 向模型平台索取的材料

- [ ] 向月之暗面（Kimi）索取所用生成式/深度合成服务的算法备案编号、备案主体和适用能力说明。
- [ ] 向火山引擎索取所用图片生成/编辑服务的算法备案编号、备案主体和适用能力说明。
- [ ] 向阿里云索取所用语音合成/识别服务的算法备案编号、备案主体和适用能力说明。
- [ ] 向各平台确认能否向下游小程序提供备案证明、服务开通证明或合规支持函。
- [ ] 合作协议模板优先从各平台企业控制台的合同/订单中心获取；找不到时提交官方工单或联系企业客户经理索取，保留工单号。
- [ ] 保存月之暗面、火山引擎、阿里云的合作协议/订单、企业账号实名信息和服务开通截图。
- [ ] 汇总各平台数据处理目的、数据类型、保存期限、处理地域和删除渠道，交法务核对隐私政策。
- [ ] 将上述材料按“平台-材料类型-日期”归档，确保提审人员可在同一天取到。

### 协议与隐私文本

- [ ] 法务定稿《用户协议》，删除页面中的 `TODO（法务定稿）`。
- [ ] 法务定稿《隐私政策》，删除页面中的 `TODO（法务定稿）`。
- [ ] 核对隐私政策的信息收集清单与代码一致：微信账号信息、主动输入文字、主动选择图片、主动录制语音、必要安全日志。
- [ ] 核对隐私政策的第三方清单包含微信、月之暗面（Kimi）、火山引擎、阿里云。
- [ ] 补齐信息更正、删除、注销和投诉联系渠道，并确认有人实际受理。
- [ ] 确认 AI 生成内容、AI 合成语音和“不构成医疗建议”文案符合法务意见。

## 微信后台管理员：平台配置

### 基础与域名

- [ ] 在微信后台确认 AppID 与当前运营主体匹配。
- [ ] 将生产 HTTPS API 域名加入 request 合法域名。
- [ ] 将 OSS/CDN 公开结果域名加入 download 合法域名。
- [ ] 确认所有合法域名证书有效、链路完整、无 IP 地址或临时隧道域名。
- [ ] 体验版清除“不校验合法域名”依赖后再做一轮真机测试。

### 消息推送与内容安全

- [ ] 消息推送 URL 填写 `https://生产API域名/api/mp/security/wechat-callback`。
- [ ] 消息推送 Token 与生产环境 `WECHAT_MP_CALLBACK_TOKEN` 完全一致。
- [ ] 消息格式：JSON；不要选 XML。
- [ ] 消息加密方式按当前实现选择明文模式，确认 GET 握手验证成功。
- [ ] 用一条真实媒体安全任务验证 `pass` 回调能更新状态。
- [ ] 用受控测试素材验证 `risky` 回调会删除风险文件并更新状态。

### 隐私保护指引与权限

- [ ] 在微信后台填写《小程序用户隐私保护指引》，内容与已定稿隐私政策一致。
- [ ] 在隐私指引中声明相机用途：拍摄需要修复或识别的照片。
- [ ] 在隐私指引中声明相册选择用途：选择需要处理的照片。
- [ ] 在隐私指引中声明保存相册用途：保存处理后的照片。
- [ ] 在隐私指引中声明麦克风用途：把用户说的话转换成文字。
- [ ] 开发者工具清缓存后，验证首次触发相机、相册、麦克风会出现微信官方隐私弹窗。
- [ ] 分别验证同意、拒绝、再次打开设置三条路径都有可理解的中文提示。

## 研发/运维：生产环境、构建与部署

### 后端 `.env` 全量核对

- [ ] `NODE_ENV=production`。
- [ ] `DATABASE_URL` 指向生产 MySQL，账号使用最小权限，连接已实测。
- [ ] `JWT_SECRET` 使用部署平台生成的随机长串，未出现在仓库、截图和聊天记录中。
- [ ] `WECHAT_MINI_APPID` 为当前小程序真实 AppID。
- [ ] `WECHAT_MINI_SECRET` 为部署密钥存储中的真实 Secret。
- [ ] 生产环境完全不设置 `MP_MOCK_LOGIN`，不是设置为 `false`。
- [ ] `CONTENT_SECURITY=wechat`。
- [ ] `WECHAT_MP_CALLBACK_TOKEN` 与微信后台消息推送 Token 一致。
- [ ] `MOONSHOT_API_KEY` 为真实模型密钥；`MOONSHOT_MODEL` 与 `MOONSHOT_MODEL_HEAVY` 已在平台确认可用。
- [ ] `ARK_API_KEY` 为真实模型密钥；`ARK_IMAGE_MODEL` 已在方舟控制台确认准确。
- [ ] `ARK_IMAGE_WATERMARK=true`。
- [ ] `DASHSCOPE_API_KEY` 为真实模型密钥；`DASHSCOPE_TTS_MODEL`、`DASHSCOPE_ASR_MODEL` 已开通。
- [ ] `AI_TEXT_PROVIDER`、`AI_IMAGE_PROVIDER`、`AI_TTS_PROVIDER`、`AI_ASR_PROVIDER` 与生产路由方案一致。
- [ ] `S3_ENDPOINT`、`S3_REGION`、`S3_BUCKET` 已逐项核对。
- [ ] `S3_ACCESS_KEY_ID`、`S3_SECRET_ACCESS_KEY` 使用最小权限账号并存于密钥管理服务。
- [ ] `S3_PUBLIC_BASE_URL` 可被微信真机和图片模型公网访问，链接不会 7 天后失效。
- [ ] 未使用的 Gemini、MiniMax、Manus 遗留变量保持不设置；如启用备用链路则另做合规确认。
- [ ] 对照根目录 `.env.example` 从上到下复核一次，无遗漏、无多余调试变量。

### 小程序构建环境

- [ ] `TARO_APP_RELEASE_CHANNEL=trial` 时 `TARO_APP_API_BASE_URL_TRIAL` 指向生产后端或等价提审环境。
- [ ] `TARO_APP_RELEASE_CHANNEL=release` 时 `TARO_APP_API_BASE_URL_RELEASE` 指向生产后端。
- [ ] 提审构建没有设置一次性 `TARO_APP_API_BASE_URL` 覆盖值。
- [ ] 执行 `pnpm check`、`pnpm check:mp`、离线测试和 `pnpm build:mp`，保存成功日志。
- [ ] 上传体验版前核对“我的 → 关于乐享AI”显示版本 `1.0.0`。
- [ ] 请求无鉴权 `GET /api/mp/health`，确认返回 `ok=true` 与版本 `1.0.0`。
- [ ] 检查 `/api/mp` 日志仅含 userId、路径、耗时、错误码，不含请求体、查询参数或用户输入原文。
- [ ] 检查生成 POST 无自动重试；弱网下只能由用户点击“手动重试”再次生成。
- [ ] M4 上线阶段后端固定为单进程、单副本，负载均衡不得同时把生成请求发到多个实例；当前操作号去重存储在服务进程内。
- [ ] 发布或重启前先停止接收新生成请求，至少等待 180 秒让在途生成结束，再关闭旧实例；旧实例退出后才启动新实例，不做重叠滚动发布。
- [ ] 若后续需要多副本或无损滚动发布，先立项接入共享持久幂等存储并完成扣分事务联动，本期禁止用新增 schema 临时绕过。
- [ ] 部署后验证数据库迁移停留在 M2 的 `media_check_tasks`，M4 没有新增 schema。
- [ ] 对比基线确认 `server/ai/` 无改动，仓库无真实密钥。
