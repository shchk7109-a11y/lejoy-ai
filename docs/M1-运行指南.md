# M1 小程序运行指南

## 1. 环境要求

- Node.js 20 或更新版本
- pnpm 10
- 可用的 MySQL 数据库（沿用现有 `users`、`credit_transactions` 表）
- 微信开发者工具
- 需要实际生成文案时，按 `docs/P0-模型切换验证指南.md` 配置至少一个文本模型密钥

## 2. 本地后端与 mock 微信登录

在仓库根目录执行：

```bash
cp .env.example .env
pnpm install
pnpm dev
```

编辑 `.env`，至少设置：

```dotenv
NODE_ENV=development
DATABASE_URL=mysql://用户名:密码@127.0.0.1:3306/lejoy_ai
JWT_SECRET=本地开发使用的随机长字符串
WECHAT_MINI_APPID=
WECHAT_MINI_SECRET=
CONTENT_SECURITY=off
```

`WECHAT_MINI_APPID` 与 `WECHAT_MINI_SECRET` 同时为空时，后端进入 mock 登录：任意 `wx.login` code 都会登录为同一个本地测试用户。mock 只替代微信 `code2session`，数据库和文本模型仍按正常链路工作。

真实微信登录时，同时填写 `WECHAT_MINI_APPID` 与 `WECHAT_MINI_SECRET`。后端会请求微信 `jscode2session`，按 `openid` upsert 现有 `users` 表并签发 30 天 JWT。严禁把真实 Secret 提交到仓库。

## 3. 编译并打开微信小程序

复制小程序环境示例并编译：

```bash
cp miniprogram/.env.example miniprogram/.env
pnpm check:mp
pnpm build:mp
```

在微信开发者工具中选择“导入项目”，目录选择仓库内的 `miniprogram/`。`project.config.json` 已配置：

- AppID：`wx513752af48b6cdae`
- 小程序产物目录：`dist/`
- 本地调试关闭合法域名校验

持续开发可执行：

```bash
pnpm --dir miniprogram dev:weapp
```

真机预览不能访问手机自身的 `127.0.0.1`。此时把 `miniprogram/.env` 的 `TARO_APP_API_BASE_URL` 改为手机可访问的 HTTPS 后端地址，并重新构建。

## 4. 内容安全模式

- `CONTENT_SECURITY=off`：默认，本地直接放行文本与媒体。
- `CONTENT_SECURITY=wechat`：获取并缓存微信 `access_token`，文本调用 `msgSecCheck`，媒体 URL 调用 `mediaCheckAsync`。

暖心文案接口会依次检查用户输入及三条 AI 输出；任一检查不通过都会停止返回且不扣积分。

## 5. 自动化质量检查

```bash
pnpm vitest run server/mp
pnpm check
pnpm check:mp
pnpm build:mp
```

仓库既有 `server/minimax.test.ts` 与 `server/gemini.test.ts` 会调用真实外部 API，需要对应密钥与网络，不属于 M1 离线质量门。不要为了运行它们把密钥写入代码或提交历史。

## 6. 微信开发者工具自查清单

- [ ] 登录页只有一个“微信一键登录”主按钮，点击后进入首页。
- [ ] 首页显示问候、当前积分和 5 个模块；暖心文案可进入，其余显示“即将上线”。
- [ ] 暖心文案按“场景 → 对象 → 语气”一次一问推进。
- [ ] 生成后固定展示 3 条候选，每条都有不低于 108rpx 的复制按钮。
- [ ] 复制后出现“复制成功”，结果底部固定显示“内容由 AI 生成”。
- [ ] 返回首页进入“我的”，积分减少 1，明细新增“暖心文案”。
- [ ] 任意页面无小于 28rpx 的文字；主按钮全宽且不低于 108rpx；其他点击区域不低于 96rpx。
- [ ] 未配置 Bearer token 时，受保护接口返回 401 并回到登录页。
- [ ] 真实 AppID/Secret 下可完成 `code2session`，且仓库与 Git 历史不含 Secret。
