# AI 故事会儿童照片主角参考设计

## 目标

在 AI 故事会的儿童信息步骤增加可选照片入口。用户可以拍摄或选择一张孩子照片，让后续四页故事配图参考该孩子的外貌生成主角，从而提升代入感和可玩性。

本功能不改变故事文字生成、四页逐页配图、积分或本机书架规则。孩子原照片只用于本次配图，不保存到账号、数据库、本机书架或导出的绘本页面；正常流程结束后立即删除，并由服务端一小时兜底清理。

## 已确认产品决策

- 使用同一张孩子照片直接作为四页 Seedream 配图的参考图，不额外生成角色设定图。
- 照片是可选项；未选择照片时，原有故事生成流程完全不变。
- 照片只影响绘本主角的外貌，不参与故事文字生成。
- 四页仍各调用一次配图接口，不增加图片生成次数和积分消耗。
- 原照片不随故事保存，不做账号同步，也不写入本地故事数据。
- 正常结束、失败或放弃后立即删除临时参考图；异常中断时最长保留一小时。

## 用户界面

在“故事讲给哪位小朋友”步骤增加“让孩子当故事主角（可选）”区块，保持现有一次一问、大按钮和适老化令牌。

未选照片时显示：

- “拍一张”按钮；
- “从相册选择”按钮；
- 说明：“照片仅用于本次绘本形象参考，生成结束后自动删除，不保存到帐号或故事。”

选择后显示本地预览，并提供“更换照片”和“不用照片”大按钮。照片选择前复用现有隐私授权流程；只接受常见图片格式且沿用 10 MB 上限。

照片只保存在小程序临时路径中，故事文字生成前不上传。用户删除照片、返回重选或退出流程时，清除页面状态中的临时引用。

## 架构与数据流

### 小程序

故事页新增独立的可选参考照片状态，包括本地临时路径、上传状态和服务端临时文件键。该状态不进入本机书架，不写入持久化故事结构。

生成流程如下：

1. 用户选择照片后，仅在本地预览。
2. 故事文字生成沿用现有接口，照片和照片信息均不发送给文本模型。
3. 开始逐页配图时，小程序通过故事专用上传接口上传照片一次。
4. 服务端返回当前用户名下的临时 `referenceFileKey`。
5. 四个 `/api/mp/story/page-image` 请求均携带同一个 `referenceFileKey`；现有每页幂等键和串行队列保持不变。
6. 四页队列结束后，无论成功或失败，小程序都在 `finally` 中调用清理接口。
7. 如果某页之后需要手动重试，而原临时参考图已经清理，小程序从仍有效的本地临时路径重新上传一次，仅供该次重试使用，并在请求结束后再次清理。
8. 页面卸载、重新开始故事或取消使用照片时执行尽力清理。

### 服务端临时参考图

新增故事专用临时前缀：

```text
story-refs/<当前用户ID>/<随机文件名>
```

上传接口完成格式、大小、用户身份和现有图片安全检查后才返回文件键。配图与清理接口都只接受当前登录用户自己的 `story-refs/<用户ID>/...`，拒绝外部 URL、其他前缀及其他用户文件。

清理接口为幂等操作：文件不存在也视为成功。服务端另执行按 `story-refs/` 前缀和创建时间清理的兜底任务，删除超过一小时的对象，覆盖小程序被强制关闭、断网或卸载后无法补发清理请求的情况。该机制不需要数据库表。

### 图片生成网关

`/api/mp/story/page-image` 将校验后的临时参考图解析为可访问 URL，再通过网关的故事图片配置传入 Seedream。仅 `profile: "story"` 支持此可选参数；修图、艺术画室和其他图像链路保持现状。

故事配图继续使用 `ARK_STORY_IMAGE_MODEL` 和故事专用 1K 尺寸。没有参考图时请求体与当前实现一致；有参考图时将 URL 放入 Seedream 的参考图参数，不改变 120 秒超时和逐页耗时日志。

如果当前故事图片供应商不支持参考图，服务端明确返回“当前暂不支持照片主角”，不得静默忽略照片，也不得自动改成无照片生成。

## 主角形象提示词约束

有参考照片时，四页配图提示词统一追加以下语义约束：

- 参考照片仅用于主角外貌；
- 保留孩子的脸型、发型、肤色和显著外貌特征；
- 转化为温暖、适龄的儿童绘本形象，避免证件照或过度写实效果；
- 四页保持主角年龄、五官、发型和服装一致；
- 默认参考并适度简化原照片服装；故事明确要求特殊装扮时只改变服装，不改变主角身份特征；
- 忽略照片背景、地点、其他人物、文字、水印和标识；
- 不根据照片推断或输出姓名、学校、地址等身份信息。

无参考照片时不追加上述约束，保留现有故事绘本提示词。

## 隐私与日志

- 原照片不写数据库，不写本地书架，不进入故事导出图片，也不随账号同步。
- 服务端日志不得记录照片 Base64、访问 URL、签名参数、原始文件名、孩子姓名、故事正文或完整提示词。
- 日志只记录用户内部标识、页码、是否使用参考图、供应商、模型、耗时和成功状态。
- 自动化测试只使用授权的非敏感示例图，真实儿童照片不得提交到仓库。
- 生成后的四页绘本按现有规则保存和释放，不受原照片清理影响。

## 错误处理

- 隐私授权拒绝：说明用途，并提供打开设置入口，不静默失败。
- 图片格式、大小或安全检查失败：显示“换一张照片”和“不使用照片继续”两个大按钮。
- 临时上传失败：不进入配图队列，允许换图或无照片继续。
- 某页配图失败：仅该页显示现有“重试这一页”，其余页面继续；不自动重试。
- 手动重试沿用该页原幂等键，避免重复扣积分。
- 参考图生成失败时不自动降级为无照片配图，避免四页主角不一致。
- 清理请求失败不阻断用户查看已完成绘本，由服务端一小时任务兜底。

## 测试与验收

按测试驱动顺序实施：

1. 小程序测试：未上传照片时原流程不变；选择、预览、更换和取消照片的状态正确。
2. 隐私测试：调用拍照或相册前必须完成现有隐私授权。
3. 队列测试：四页使用同一 `referenceFileKey`；成功和失败均执行清理；清理后单页重试会重新上传并再次清理。
4. 路由测试：只接受当前用户自己的 `story-refs/` 文件键，拒绝跨用户、其他前缀和外部地址。
5. 网关测试：故事 profile 有参考图时传入 Seedream 图片参数，仍使用 1K；无参考图及其他图片业务请求保持不变。
6. 提示词测试：包含外貌保留、背景忽略、四页一致和隐私约束。
7. 幂等与积分测试：某页失败后手动重试不重复扣积分。
8. 清理测试：即时清理幂等，超过一小时的临时对象会被兜底删除。
9. 运行类型检查、完整单测和 `pnpm build:weapp:prod`，生产 API 地址校验必须通过。
10. 使用授权的非敏感人物示例图进行一次真实 Seedream 四页实调，人工核对主角相似度、四页一致性和背景忽略效果。
11. 部署后执行健康检查；验收日志不得出现照片内容或用户输入原文。

## 非目标

- 不生成额外角色设定图，不增加第五次图片生成。
- 不做人脸识别、身份认证、人物搜索或年龄判断。
- 不保存原照片到帐号、数据库、本机书架或长期 OSS。
- 不修改故事文字模型、朗读音色、本机最多六本故事或相册导出规则。
- 不新增数据库表，不改变积分价格和现有生成类接口禁止自动重试的约束。
